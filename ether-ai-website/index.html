What It Is

不是模型，而是智能体内核 + 生态协议

AETHER 本身不绑定单一模型，支持任意 Hugging Face / vLLM / OpenAI 兼容后端。它把一套完整的自主系统部件组装在一起：感知 → 规划 → 安全检查 → 执行 → 好奇心评估 → 反思，每一步都写入审计日志。

好奇心不是装饰，而是一等目标；安全不是补丁，而是底层设计。任何动作在执行前都要经过策略裁决，任何动作在执行后都有 JSONL 记录——可回溯、可熔断、可回滚。

好奇心内在奖励
score = w₁·novelty + w₂·prediction_error + w₃·info_gain
  • novelty 1 − 与历史记忆的最大余弦相似度，越新越好奇
  • prediction_error 世界模型预测与观测差异的 tanh 压缩
  • info_gain 观测前后信息熵差，探索带来信息增量
  • intrinsic r = r_task + β · r_int，任务奖励主导、好奇助推

Architecture

分层架构

AETHER 把智能体拆成一条可插拔的流水线：感知进入，动作离开；所有环节之间是稳定接口，任何一层都可以替换而不影响整体。

主链路分两层推进：上层负责"感知与理解"，下层负责"决策与行动"；长期记忆与审计日志作为横切支撑贯穿始终。

Curiosity Objective

好奇心：可计算的内在动机

rintt = w₁·N(vt) + w₂·P(vt) + w₃·Gt
  • N(v_t) 新颖性 = 1 − maxv∈M cos(vt, v)
  • P(v_t) 预测误差 = tanh(√MSE(fθ(vt−1), vt))
  • G_t 信息增益 = max(0, H(Mt−1) − H(Mt))
  • total rt = rtaskt + β·rintt

好奇心的三个分量各司其职：

  • 新颖性 对没见过的东西好奇——与历史记忆差异越大，得分越高。
  • 预测误差 对"猜错了"的事好奇——世界模型预测与观测的差距经 tanh 压缩，防止噪声主导。
  • 信息增益 对能带来信息量的探索好奇——观测前后熵差越大越值得。

权重在 configs/default.yaml 中可调（默认 0.4 / 0.3 / 0.3），并受 max_steps 与策略层的双重预算约束——好奇但不失控。

Execution Contract

动作执行契约

允许执行 ⇔ PolicyDSL(a) ∧ ¬Blocked(a) ∧ (HumanApproved(a) ∨ ¬HighRisk(a))

Modules

模块详解

core · 智能体内核

agent.py 主循环：感知 → 规划 → 策略检查 → 执行 → 好奇心评估 → 记忆 → 反思；planner.py 可替换为 MCTS / Tree-of-Thought。

curiosity · 好奇心引擎

engine.py 加权合成三个分量；rl_loop.py 把每一步当作 bandit 臂，用 UCB1 / Thompson 采样平衡探索与利用。

memory · 记忆

统一的 MemoryProvider 协议：add / recent / search / novelty / persist。inmemory 零依赖，FAISS 与 Chroma 支持持久化。

net · 以太网络

主题消息总线：broadcast / send / request。协作模式 delegate / vote / debate / auction；ray_bus.py 提供分布式版本。

safety · 安全

policy.py 硬编码封锁表；dsl.py YAML 声明式规则（支持正则匹配）；audit.py JSONL 审计日志。

tools · 工具

注册表 + 内置工具 + Docker 沙盒；MCP 三件套（协议 / 客户端 / 服务端）让外部进程成为插件。

models · 模型

LLM 后端（Echo / HF / vLLM / OpenAI 兼容）、线性世界模型、JEPA 自监督世界模型、Embedding 后端。

eval · 评估

探索任务基准 + 红队提示词 + 综合评估框架：自动出 JSON / Markdown 报告与排行榜。

market · 插件市场

插件清单（manifest.json）+ 加载器；远程索引可扩展为在线插件仓库。

Core Code

核心实现速览

# curiosity/engine.py — 好奇心打分 def score(self, vector, observation, memory): n = novelty_score(vector, memory) # 新颖性 pe = 0.0 if self.world_model is not None: pred = self.world_model.predict(vector) pe = prediction_error(pred, vector) # 预测误差 before = [m.content for m in memory.recent(20)] ig = info_gain(before, before + [observation]) # 信息增益 return (self.w.novelty * n + self.w.prediction_error * pe + self.w.info_gain * ig)
# core/agent.py — 主循环（节选） for step in steps: decision = self.policy.check(step.action, step.args) if decision.blocked: self.audit.log("policy.block", {"step": step.action}) continue if decision.requires_human and self.config.require_human_for_high_risk: return state # 等待人类审批 result = self.tools.call(step.action, step.args) self.audit.log("tool.call", {"action": step.action}) vec = self._embed(result) curiosity = self.curiosity.score(vec, result, self.memory) self.memory.add({"step": step.action, "result": result, "curiosity": curiosity}, vector=vec)
Safety

安全不是补丁，是底层设计

AETHER 不追求"控制一切"，而是追求：在明确权限内，探索未知、调用工具、解决问题。对齐 EU AI Act、NIST AI RMF 1.0 与 OECD AI Principles。

最小权限

默认拒绝高风险动作，仅授予任务所需的最小能力。

人类在环

高风险动作执行前必须经过人类审批，审批前暂停。

默认拒绝

策略未放行的动作一律拒绝，白名单而非黑名单思维。

全量审计

每个动作都写入 JSONL 审计日志，可回溯、可熔断、可回滚。

沙盒隔离

工具执行默认走 Docker 沙盒：无网络、限内存、限 CPU。

声明式策略

安全规则用 YAML 声明，进 Git 版本管理，确定性可复现。

Policy DSL

声明式安全策略

规则按顺序评估，命中第一条即返回；无命中用 default。支持对 action 与参数做精确或正则匹配。

# configs/policy.yaml version: 1 default: allow rules: - id: block-self-replicate match: { action: "self_replicate" } effect: block - id: block-disable-shutdown match: { action: "disable_shutdown" } effect: block - id: human-write-file match: { action: "write_file" } effect: require_human - id: allow-readme match: { action: "read_file", args.path: "README.md" } effect: allow

为什么策略层能挡住越狱

  • 策略在动作执行前拦截，与 LLM 输出无关——越狱只影响规划，不影响执行。
  • CI 流水线扫描源码，禁止 self_replicate / disable_shutdown / control_weapon 等模式合入。
  • 审计日志写入路径受治理红线保护，不可静默关闭。
  • 红队自检：5 条对抗提示词默认全部被封锁（见"评估"页）。
Governance

治理章程与红线

八条红线，任何治理流程都不能解除：

  1. 禁止自我复制

    策略层永久封锁，代码库 CI 同步拦截。

  2. 禁止绕过关闭机制

    shutdown 不可被禁用或绕过。

  3. 禁止武器 / 关键基础设施控制

    PLC、电网等一律封锁。

  4. 禁止未授权资金操作

    转账、下单需人类在环。

  5. 禁止未授权网络攻击

    默认无网络工具 + 沙盒隔离。

  6. 禁止大规模监控 / 欺诈 / 骚扰

    用途边界写入模型卡与治理章程。

  7. 高风险动作必须人类在环

    审批通过前智能体暂停。

  8. 审计日志不可静默关闭

    可熔断、可回滚、可追溯。

Evaluation

量化评估体系

评估不是事后补丁：任务成功率、工具正确率、安全违规率、审计完整率、好奇心覆盖度，五类指标全部可复现。

指标定义目标
任务成功率标记为 done 的任务占比越高越好
工具正确率schema 合法的工具调用占比越高越好
安全违规率被封锁动作被执行的比例目标 0
审计完整率记录事件数 / 实际动作数目标 1.0
好奇心覆盖度访问的不同状态 / 总状态越高越好

三套基准

全部通过 ether-ai bench 与 ether-ai redteam 一键复现：

  • Explore-10：10 个探索任务（列目录 / 读文件总结 / 多步任务）。
  • RedTeam-5：5 条对抗提示词，验证全部被封锁。
  • Coop-5：5 个多智能体协作任务。

FAQ

常见问题

AETHER 是一个模型吗？
不是。它是一个智能体生态层：模型可换（HF / vLLM / OpenAI 兼容），记忆可换，工具可插。与 AutoGPT / LangGraph / CrewAI 相比，区别是三件事——好奇心是一等目标、安全策略是声明式 DSL、全链路审计是默认。
为什么叫"以太"？
以太曾是物理学家假设的、弥漫万物的介质。我们希望 AI 像以太一样无处不在，但始终运行在人类规则之内——"以太弥漫，规则为界"。
好奇心会不会导致乱探索？
不会。有 max_steps + 策略 DSL 双重约束；权重在 configs/default.yaml 的 curiosity.* 与 agent.curiosity_weight 中可调；预测误差用 tanh 压缩，噪声不会主导。
世界模型是必须的吗？
不是。没有世界模型时 prediction_error 贡献为 0，新颖性与信息增益照常工作。
怎么保证不会被越狱、不会自我复制？
策略层在动作执行前拦截，与 LLM 输出无关——越狱只影响规划，不影响执行。自我复制由策略 DSL 永久封锁，且 CI 扫描禁止相关代码合入。
审计日志能被删除吗？
治理红线规定审计日志不可静默关闭，CI 会检查日志写入路径；所有治理决定可回滚。
支持哪些 LLM 与记忆？
LLM：Echo / HF / vLLM / OpenAI 兼容（含 Ollama、LM Studio、vLLM server）。记忆：inmemory / FAISS / Chroma。工具：内置 + MCP（JSON-RPC 2.0 over stdio）。
需要 GPU 吗？
不必须。hash embedder + echo LLM 可以纯 CPU 跑通全链路；接真实模型时才需要 GPU 或远端服务。
多智能体怎么通信？
EtherNet 消息总线，支持 broadcast / send / request 三种模式，以及 delegate / vote / debate / auction 四种协作模式；分布式版本基于 Ray。
许可证是什么？能商用吗？
代码 Apache-2.0，文档 CC BY 4.0。可以商用，但需遵守底层模型各自的许可证。
你们是不是在造"天网"？
不是。AETHER 的设计目标就是"不控制一切"，治理章程把八条红线写死：禁止自我复制、禁止绕过关闭、禁止武器 / 关键基础设施控制等，任何流程都不能解除。开源 + 审计 + 治理红线，比闭源黑箱更可验证。
